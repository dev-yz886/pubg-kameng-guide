## 三、 Vanguard 战争迷雾底层架构：为什么无畏契约能做到“硬件级防透视”

在传统 CS 或战地等引擎中，服务器为了保证画面平滑，往往会将全地图所有玩家的坐标每帧无差别广播给所有客户端。这就给予了本地作弊软件致命的攻击面：**画面即使被墙壁遮挡，但敌人坐标早已潜伏在本地内存中。**

| 安全防护维度 | 传统 FPS 广播架构 | 无畏契约 Vanguard 战争迷雾 (Fog of War) |
| :--- | :--- | :--- |
| **客户端内存数据** | 全地图所有敌人坐标实时存在 | 墙后遮挡敌人数据被服务器严格剔除，内存根本无数据 |
| **遮挡剔除执行方** | 客户端 GPU 本地执行深度测试（Z-Buffer） | 服务器端预计算可见集（PVS）与动态射线追踪裁切 |
| **网络封包暴露面** | 敌人在掩体后移动依然接收移动封包 | 仅在敌人即将走出掩体的前几十毫秒才发送位置包 |
| **透视作弊有效性** | 全图透视框与骨骼绘制极易实现 | 掩体后完全黑屏，强行读取只能导致空指针异常与模型瞬移 |

Riot 官方安全工程公开披露，服务器在派发每一包游戏状态前，会调用极为高效的服务器帧剔除算法（开销控制在服务器帧时间的 2% 以下）。如果敌人在物理空间上被三堵水泥墙阻隔，服务器对你的客户端只会说：“这个世界上现在没有这个人。”

正如网络安全大师所言：**反透视真正的战场，不在准星中央，而在服务器决定下一包数据该不该发送的那一瞬间。**
